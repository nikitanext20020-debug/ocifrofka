# Реальные адреса Богородского округа в автопилоте

## Цель

Автопилот должен создавать синтетические строки только с настоящими парами «населённый пункт + элемент улично-дорожной сети» Богородского городского округа. Номер дома может быть синтетическим. Во время работы приложения интернет, внешний API и отдельные токены не используются.

## Причина дефекта

Сейчас генератор получает только дополнительный промпт генерации. Большая справочная инструкция со списком улиц передаётся следующему шагу `fill-gaps`, который работает лишь с пустыми ячейками. Если модель уже заполнила адрес, второй шаг его не проверяет и не исправляет. Дополнительно примеры таблицы часто содержат Ногинск, поэтому модель повторяет его чаще остальных населённых пунктов и придумывает недостающие улицы.

## Источник данных

В репозитории хранится компактный снимок адресных элементов Богородского городского округа, подготовленный по Государственному адресному реестру ФИАС. Вместе с данными фиксируются:

- источник;
- дата актуальности снимка;
- муниципальное образование;
- тип и название населённого пункта;
- тип и название элемента улично-дорожной сети.

В справочник включаются только действующие пары из округа. Населённые пункты без зарегистрированного именованного элемента улично-дорожной сети не участвуют в генерации. Дубликаты после нормализации регистра, `ё/е`, пробелов и сокращений запрещены.

Обновление справочника является отдельной операцией разработчика и не выполняется приложением во время работы. Обновлённый снимок проходит те же автоматические проверки перед коммитом.

## Архитектура

### Локальный каталог

Новый серверный модуль загружает снимок и предоставляет небольшие чистые функции:

- получить все доступные населённые пункты;
- выбрать адресную пару по порядковому номеру строки;
- сформировать канонический синтетический адрес;
- проверить принадлежность пары каталогу.

Каталог не импортируется клиентскими компонентами и не увеличивает клиентский JavaScript.

### Выбор адресов

Выбор выполняется детерминированно по `sequenceStart` и индексу создаваемой строки:

1. Сначала по кругу выбирается населённый пункт, поэтому Ногинск не получает преимущество из-за большего количества улиц.
2. Внутри выбранного населённого пункта улицы также перебираются по кругу.
3. Номер дома формируется синтетически и стабильно из порядкового номера строки.

Такой порядок обеспечивает разнообразие между последовательными циклами автопилота и воспроизводимость тестов. В каталоге обязательно присутствуют как минимум Ногинск, Старая Купавна, Электроугли и Мамонтово.

### Поток генерации

Клиент передаёт в `/api/table/generate` индекс адресной колонки, полученный после анализа таблицы. Route Handler до вызова модели назначает каждой строке допустимую адресную пару.

Модель продолжает создавать остальные поля. После разбора её ответа сервер всегда перезаписывает адресную ячейку заранее назначенным каноническим адресом. Значение модели для адреса не считается доверенным и не может попасть в результат.

Справочная инструкция пользователя продолжает применяться к заполнению пропусков и другим оговорённым правилам, но не расширяет адресный каталог и не может разрешить несуществующую улицу.

## Ошибки и защита

- Если переданный индекс адресной колонки выходит за границы таблицы, запрос отклоняется с ошибкой 400.
- Если адресная колонка отсутствует, генератор сохраняет прежнее поведение для таблиц без адресов и не добавляет адрес в постороннюю колонку.
- Если каталог пуст, повреждён или не содержит обязательные контрольные населённые пункты, генерация завершается ошибкой до обращения к модели.
- Повторный запрос использует те же назначенные адреса: retry не меняет географию строк.
- В логах не сохраняются полные сформированные адреса.

## Проверки

Автоматические тесты должны доказать следующие свойства:

1. Каталог содержит только уникальные непустые пары и обязательные населённые пункты.
2. Последовательный выбор охватывает Старую Купавну, Электроугли, Мамонтово и другие доступные населённые пункты без постоянного перевеса Ногинска.
3. Каждая выбранная пара существует в локальном каталоге.
4. Выдуманный моделью адрес заменяется каталогизированным адресом.
5. Первый вызов и retry получают одинаковые назначения.
6. Некорректный индекс адресной колонки отклоняется.
7. Таблица без адресной колонки остаётся совместимой с текущим генератором.

После модульных и маршрутных тестов выполняются `npm run lint`, `npm run typecheck`, `npm test` и `npm run build`.

## Не входит в задачу

- Проверка существования конкретного номера дома.
- Сетевые обращения к ФИАС во время генерации.
- Автоматическое обновление справочника в развёрнутом приложении.
- Исправление реальных адресов, распознанных из пользовательских документов.
